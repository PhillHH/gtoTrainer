## 4. Schnittstellen, auf denen T3.2 und T3.3 aufsetzen

Vollständig in [`docs/INTERFACES.md`](../INTERFACES.md) Abschnitt 12.

**Sektionen gezielt laden** (Kontextdisziplin — eine Sektion, nicht ein Kapitel):

```ts
const [section] = await db
  .select()
  .from(bookSection)
  .where(
    and(eq(bookSection.sectionKey, 'ch07/small-blind-pfi-strategy'), isNull(bookSection.removedAt)),
  );
```

Für Übersichten reicht eine Projektion ohne `body` — das ist die mit Abstand
größte Spalte.

**Range-Charts für die Vision-Pipeline abrufen:**

```ts
const charts = await db
  .select({ id: bookAsset.id, path: bookAsset.relativePath, caption: bookAsset.captionRaw })
  .from(bookAsset)
  .where(
    and(
      eq(bookAsset.assetType, 'hand_range'),
      eq(bookAsset.filePresent, true),
      isNull(bookAsset.removedAt),
    ),
  )
  .orderBy(bookAsset.ordinal);
```

**Zusage an T3.3/T3.4:** `book_asset.id` ist stabil, solange das Asset in der
Quelle steht. Ein erneuter Buchimport legt keine Zeile neu an und löscht keine —
Chart-Daten dürfen daran hängen. Entfallene Einträge bekommen `removed_at`
gesetzt.

**Sollwerte für die Validierung** stehen in `book_asset.caption_actions`
(`[{ action, percent }]`), der unveränderte Beleg daneben in `caption_raw`.

  Diagram-Nummern): mehrteilige Diagramme über zwei Bilder. Für T3.3 ohne

- **Kontingent für T3.3:** 348 Vision-Aufrufe. Vor dem Vollausbau steht der
  Kalibrierungslauf aus Scope-Delta 3 (Stichprobe, ADR, dann Massenlauf).
