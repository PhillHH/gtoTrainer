## 1. Was nach AP1 existiert

pnpm-Monorepo mit lauffähigem, containerisiertem Stack und automatisierter
Qualitätsschranke.

| Workspace         | Paket           | Inhalt                                                 |
| ----------------- | --------------- | ------------------------------------------------------ |
| `apps/backend`    | `@gto/backend`  | Fastify 5, `/healthz` + Auth-API, Drizzle, Migrationen |
| `apps/frontend`   | `@gto/frontend` | React 18, Router 7, Login, Sidebar-Shell, Dark Mode    |
| `packages/shared` | `@gto/shared`   | Health- und Auth-Verträge — von beiden Apps genutzt    |

**Datenbank:** Postgres 16, fünf Tabellen (`user`, `session`, `config`,
`llm_call_log`, `job_queue`), versionierte Drizzle-Migrationen, idempotenter
Seed, abgesichertes Reset.

**Auth:** argon2id (Timing-gleich bei unbekanntem Konto), Session als
SHA-256-Hash in der DB — Klartext nur im HttpOnly-Cookie, CSRF per
Double-Submit, Rate-Limit nur auf Fehlversuchen, `pnpm auth:set-password`,
TOTP als Hook (aus).

**Qualität:** 71 Unit-/Integrationstests (2 shared, 50 Backend, 19 Frontend) und
1 Browser-Smoke-E2E. GitHub Actions prüft bei Push auf `main` und bei Pull
Requests: install → lint → migrate → test → build, danach den E2E-Lauf.

### Deployment-Topologie (tatsächliche Ports)

```
Internet :80/:443 → Host-Nginx (systemd, root) ─┬─ /api/*, /healthz → 127.0.0.1:3010 (Container gto-backend, intern :3000)
                                                 └─ alles andere    → /home/phillip/gto-static (statische Assets, SPA-Fallback)
                                                                       gto-backend → gto-postgres:5432
                                                                       Host-Port 127.0.0.1:55434, Volume gto-pgdata
```

Öffentlich ist ausschließlich der Host-Nginx; alle Container-Ports sind an
`127.0.0.1` gebunden und kommen aus Pflichtvariablen. Das Frontend läuft
bewusst **nicht** als Container ([ADR-0016](../DECISIONS.md)).

## 3. Offene Punkte

- **Host-Nginx-vhost und TLS** — vorbereitet, nicht eingespielt (Root nötig,
  siehe Kasten oben). Damit ist die App aktuell nur über `127.0.0.1:3010`
  erreichbar, nicht über die Domain.
- Die fünf Bereichsseiten sind Platzhalter; Inhalte kommen in AP5–AP9.
- `llm_call_log` und `job_queue` sind leer bis AP2 bzw. bis zum ersten Worker.
- TOTP ist nur ein Hook; der Rate-Limit-Zähler liegt im Prozessspeicher.
- Vor dem ersten Login muss `pnpm auth:set-password <name>` laufen.
- Backend-Tests setzen einen laufenden Postgres-Container voraus (`pnpm db:up`).

## 4. Risiken und Umgebungs-Besonderheiten

| Thema           | Befund                                            | Umgang                                                                                                          |
| --------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **Root-Rechte** | `NoNewPrivs=1` — `sudo` im Agenten gesperrt       | vhost/TLS als manueller Root-Schritt dokumentiert                                                               |
| Ports           | 3000, 3001, 5173, 5432, 55432, 55433 fremd belegt | Backend **3010**, Postgres **55434**, Dev **5174**, E2E **3020/5180** — alle über Variablen                     |
| Docker-Subnetze | Standardpools durch 33 fremde Netze erschöpft     | eigenes Subnetz `10.89.0.0/24` ([ADR-0006](../DECISIONS.md))                                                    |
| `NODE_ENV`      | steht auf dem Host auf `production`               | Dockerfiles und CI setzen explizit `development`                                                                |
| Node 20         | drei Pakete auf ältere Fassungen gepinnt          | `@fastify/cookie@11.1.0`, `jsdom@26`, `@testing-library/jest-dom@6` — bei weiterem Zuwachs Node-Upgrade erwägen |
| GNU Make        | nicht installiert                                 | `pnpm` bzw. die Skripte in `deploy/`                                                                            |

Der Host ist geteilt: Jeder neue veröffentlichte Port muss vorher geprüft und
über eine Variable geführt werden — nie hart verdrahten.
