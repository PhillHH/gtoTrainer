### T1.4 — Frontend-Shell

- **API-Client** (`src/api/client.ts`) ist die **einzige** Stelle mit `fetch`:
  `credentials: 'include'`, CSRF-Ablauf exakt nach INTERFACES.md, typisierte
  Fehlerarten (`unauthenticated`, `rate_limited`, `csrf_failed`, `client`,
  `server`, `network`).
- **Auth-Zustand** als React Context, `checking` → `authenticated`/`anonymous`
  ([ADR-0012](../DECISIONS.md)). Beim Start wird `/api/auth/me` abgefragt; bis
  zur Antwort läuft ein Ladezustand — der Login-Screen blitzt angemeldeten
  Nutzern nie auf.
- **Routing** (React Router 7, [ADR-0011](../DECISIONS.md)): `/login`
  öffentlich; Dashboard und die fünf Bereiche unter **einem** Guard
  (`RequireAuth`), der auf `/login` umleitet und danach zum ursprünglichen Ziel
  zurückführt; 404-Route.
- **Login-Screen** mit Ladezustand, Enter-Absenden, Fehlermeldungen —
  unterscheidet bewusst nicht zwischen unbekanntem Benutzer und falschem
  Passwort; 429 hat eine eigene Meldung.
- **Layout** mit Sidebar (Lernen · Drills · Turniere · Material ·
  Einstellungen), erkennbarem Aktiv-Zustand, Kopfzeile mit Benutzername,
  Theme-Umschalter und Logout. Die fünf Bereichsseiten sind Platzhalter mit
  Hinweis auf das zuständige AP.
- **Design-Tokens** als CSS Custom Properties, helles und dunkles Set über
  `data-theme` am `<html>` ([ADR-0013](../DECISIONS.md)). Startwert folgt
  `prefers-color-scheme`, manuelle Wahl in `localStorage` — die einzige
  erlaubte `localStorage`-Nutzung. Keine hartkodierten Farben in Komponenten.
- **Kein CORS nötig:** Der Vite-Dev-Server proxyt `/api` und `/healthz` ans
  Backend, wie später der Host-Nginx. Das Backend wurde **nicht** geändert
  ([ADR-0015](../DECISIONS.md)).

## Offene Punkte

- Kein Backend-/Frontend-Container, kein Nginx, kein Deploy, kein Backup — T1.5.
- Keine CI, kein Playwright — T1.6.
- Die fünf Bereichsseiten sind Platzhalter; Inhalte kommen in AP5–AP9.
- `llm_call_log` bleibt leer bis AP2, `job_queue` bis zum ersten Worker.
- TOTP ist nur ein Hook, nicht implementiert.
- Rate-Limit-Zähler liegt im Prozessspeicher (nach Neustart leer).
- Es existiert **kein Benutzer** — vor dem ersten Login
  `pnpm auth:set-password <name>` ausführen.
- Backend-Tests brauchen einen laufenden Postgres-Container (`pnpm db:up`);
  Frontend-Tests nicht. Für die CI in T1.6 wird ein Service-Container gebraucht.

## Risiken

- **Geteilter Host.** Ports und Docker-Subnetze sind knapp; jeder neue
  veröffentlichte Port muss vorher geprüft und über eine Variable geführt werden.
- **Node 20 wird eng.** Drei Pakete mussten gepinnt werden, weil ihre aktuellen
  Fassungen Node ≥ 22 verlangen (`@fastify/cookie@11.1.0`, `jsdom@26`,
  `@testing-library/jest-dom@6`). Häuft sich das weiter, wird ein Node-Upgrade
  als eigene Entscheidung fällig.
