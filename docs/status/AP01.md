### T1.5 — Deployment

- **Backend-Image**: mehrstufig, Node 20.19.6-alpine, **non-root** (`node`,
  uid 1000), nur Produktions-Abhängigkeiten (`pnpm deploy`), 158 MB. Enthält
  `dist/`, `drizzle/` und `node_modules` — kein Quellcode, keine Testdateien.
- **Frontend**: wird containerisiert **gebaut**, aber als statische Dateien vom
  Host-Nginx ausgeliefert — kein Frontend-Container, kein zweiter Reverse Proxy
  ([ADR-0016](../DECISIONS.md)).
- **Compose**: `postgres` + `backend`, beide `restart: unless-stopped`, beide
  mit Healthcheck; `depends_on: condition: service_healthy`. Alle Host-Ports
  kommen aus Pflichtvariablen und sind an `127.0.0.1` gebunden
  ([ADR-0018](../DECISIONS.md)).
- **Migrationen** laufen als eigener, einmaliger Schritt im Deploy vor dem
  Backend-Start — Fehler brechen den Deploy ab ([ADR-0017](../DECISIONS.md)).
- **Skripte**: `deploy/deploy.sh` (idempotent, `set -Eeuo pipefail`),
  `deploy/backup.sh` (pg_dump + `data/`, Zeitstempel, Rotation),
  `deploy/restore.sh` (standardmäßig in eine **separate** Prüfdatenbank),
  `deploy/smoke-check.sh`.
- **vhost** `deploy/nginx/gto.growento.com.conf`: Proxy auf das Backend,
  statische Auslieferung, SPA-Fallback, `/healthz` öffentlich, gzip,
  `client_max_body_size 25m`, korrekte `X-Forwarded-*`-Header.
- **Verifiziert**: beide Container `healthy`, `/healthz` → 200, Login über den
  Container-Stack erfolgreich, Cookie trägt `Secure`, zwei Deploy-Läufe je
  Exit 0, Backup erzeugt, **Restore tatsächlich durchgeführt und geprüft**.

## Offen: HTTPS und vhost (Root erforderlich)

Alles ist vorbereitet; es fehlen nur die Schritte, die Root brauchen:

```bash
sudo cp /home/phillip/gto/deploy/nginx/gto.growento.com.conf \
        /etc/nginx/sites-available/gto.growento.com.conf
sudo ln -sfn /etc/nginx/sites-available/gto.growento.com.conf \
             /etc/nginx/sites-enabled/gto.growento.com.conf
sudo chmod o+x /home/phillip
sudo chmod -R a+rX /home/phillip/gto-static
sudo nginx -t && sudo systemctl reload nginx
curl -i http://gto.growento.com/healthz          # erwartet: 200

sudo certbot --nginx -d gto.growento.com --redirect
curl -I http://gto.growento.com/                 # erwartet: 301 -> https
curl -I https://gto.growento.com/healthz         # erwartet: 200
sudo certbot renew --dry-run
```

Danach in der `.env` `COOKIE_SECURE=true` und
`ALLOWED_ORIGINS=https://gto.growento.com` setzen und
`./deploy/deploy.sh --no-pull` ausführen.

## Risiken

- **Geteilter Host.** Ports und Docker-Subnetze sind knapp; jeder neue Port
  muss vorher geprüft und über eine Variable geführt werden.
- **Node 20 wird eng.** Drei Pakete sind gepinnt, weil ihre aktuellen Fassungen
  Node ≥ 22 verlangen (`@fastify/cookie@11.1.0`, `jsdom@26`,
  `@testing-library/jest-dom@6`).
- **Deploy und Host-Nginx sind entkoppelt.** Ändert sich `BACKEND_HOST_PORT`
  oder `FRONTEND_STATIC_DIR`, muss der vhost von Hand nachgezogen werden.
